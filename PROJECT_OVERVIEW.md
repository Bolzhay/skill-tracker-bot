# Skill Tracker Bot — обзор проекта

Telegram-бот для прокачки любого навыка. Называешь навык (пиксель-арт, риторика, шахматы…), и бот строит дерево уровней под твой старт, выдаёт задания, строго проверяет присланные пруфы (фото, голос, видео, текст) и ведёт прогресс: XP, серия дней, ранги, бейджи и сравнение «тогда vs сейчас». Работает только на бесплатных моделях и бесплатных квотах.

Этот файл — обзор «что умеет и как устроен». Установка и запуск — в [README.md](README.md), принятые решения и открытые вопросы — в [skill_tracker_brief.md](skill_tracker_brief.md).

## 1. Что умеет

### Скиллы и дерево уровней
- **Онбординг из трёх вопросов** (самооценка 1–10, что пробовал, цель) — диалог с состояниями (FSM). Скилл создаётся только после ответов: брошенный диалог ничего не оставляет. Ответы сохраняются и потом калибруют и дерево, и задания.
- **Дерево уровней строит ансамбль моделей в фоне:** черновик → критика → доработка → финальный судья. Обычно 8–15 уровней, у каждого цель и проверяемые критерии. Язык и сложность подстроены под самооценку: без профессионального жаргона и без привязки к софту, который человек не называл.
- Если модели сбойнули, приходит кнопка «построить заново». Скилл без уровней можно удалить.
- Скиллов может быть несколько. Если скилл один, команды не спрашивают название, если несколько — предлагают выбрать кнопкой.

### Задания
- Выдаются **только по команде или кнопке**, без рассылок. Одно задание — одна конкретная цель, с короткой подсказкой и типом пруфа.
- **Антиповтор в две ступени.** Сначала бесплатный локальный фильтр: похожесть слов с последними 10 заданиями (порог 0,5). Затем проверка смысла второй моделью. Если похоже — до 3 переделок со сменой «оси» (материал, контекст, ограничение).
- **Wildcard:** каждое 6-е задание нарочно ломает шаблон.
- **`/hint`** — развёрнутая подсказка (инструменты, шаги, на что смотреть) и **настоящие ссылки на YouTube**: модель лишь формулирует 1–3 поисковых запроса, а ролики находит YouTube Data API. Выдуманных ссылок нет.
- `/history` — последние 5 заданий со статусом.

### Пруфы и оценка
- **Принимает:** фото, картинку файлом (без сжатия — важно для пиксель-арта), голосовое, аудио, видео и «кружки», обычный текст. Файлы до 20 МБ (предел Telegram для ботов).
- Звук и видео расшифровывает **Whisper локально**, на твоём компьютере: бесплатно и без отправки аудио в облако. Расшифровка показывается, а ошибки распознавания оценку не снижают. У видео оценивается только звук.
- **Строгая оценка:** два независимых анализа фото разными моделями со зрением, параллельно. Затем модель-«скептик» («ищи недочёты, не хвали без оснований») выносит вердикт: отзыв, зачёт или незачёт, что хорошо, что улучшить. Оценивается именно **задание**, а не весь уровень.
- **Пересдача без команд.** Засчитанный пруф закрывает задание, незасчитанный оставляет его открытым: следующее сообщение и есть пересдача. Если оценка сорвалась из-за моделей, пруф не теряется. `/retry` снова открывает приём пруфа, в том числе после перезапуска бота.

### Прогресс и геймификация
- **Левелап** — после 3 засчитанных заданий на уровне (не по XP).
- **XP:** засчитано — 10 плюс бонус за серию (до +10), не засчитано — 2.
- **Серия дней** по скиллу, по местной дате (по умолчанию UTC+5): любая попытка продлевает, пропуск дня обнуляет.
- **Ранги:** Новичок → Ученик (50 XP) → Упорный (150) → Практик (400) → Мастер (800) → Легенда (1500).
- **Бейджи:** первое засчитанное задание, 10 заданий, первый левелап, wildcard покорён, серия 3, 7 и 30 дней. Выдаются один раз.
- **«Тогда vs сейчас»** (`/progress`): первая и последняя засчитанные фото-работы рядом и честный разбор прогресса. Для этого каждый пруф архивируется.

### Люди и доступ
- **Закрытый бот (whitelist).** Пока владелец не активировал бота командой `/claim <код>`, он не отвечает никому. Дальше пускает только тех, кого добавил владелец (`/allow <id>`, `/deny <id>`). Чужому показывает его Telegram ID.
- **У каждого пользователя своё:** скиллы, задания, архив — всё лежит под `users/{id}`. Данные старой односкилловой схемы при активации переносятся под владельца автоматически.

### Интерфейс
Постоянное меню («Мои скиллы», «Новый скилл»), inline-кнопки под сообщениями (задание, подсказка, пруф, история, прогресс), команды в меню Telegram, `/cancel` выходит из любого диалога. На устаревшие кнопки и неизвестные команды бот отвечает, а не молчит.

## 2. На чём построен

| Что | Чем |
|---|---|
| Язык и бот | Python 3.14, aiogram 3: long polling, FSM, middleware, роутеры |
| База данных | Firebase Firestore (firebase-admin); правила закрыты (deny-all), бот ходит по сервисному ключу |
| Модели | Бесплатные: OpenRouter (nemotron-3-ultra, gemma-4-31b, dots-3-note-preview) и напрямую Gemini API Google (Gemma 4) |
| Речь в текст | faster-whisper (модель small, на процессоре), свой декодер на PyAV |
| Ссылки на видео | YouTube Data API v3 (`search.list`) |
| Тесты | pytest, pytest-asyncio, фейковые Firestore и Telegram |
| Код | Git, приватный репозиторий на GitHub |

Зависимостей всего пять: aiogram, firebase-admin, python-dotenv, httpx, faster-whisper.

## 3. Как устроен

### Путь сообщения
```
Telegram → aiogram (polling) → проверка доступа (whitelist) → роутеры по порядку → обработчик
                                                                  ├─ db.py → Firestore
                                                                  ├─ llm/*_pipeline → call_model_json → OpenRouter / Google
                                                                  ├─ transcribe.py → Whisper
                                                                  └─ youtube.py → YouTube
```
Порядок роутеров важен: сначала меню и команды (они сильнее текстовых ответов в диалогах), последним — «ловец всего остального».

### Структура кода
```
bot/
  main.py           сборка бота: роутеры, команды, прогрев Whisper, запуск
  config.py         настройки из .env (.env главнее переменных ОС)
  access.py         whitelist (middleware)
  db.py             весь слой Firestore (users/{id}/…)
  gamification.py   чистые правила: XP, серия, ранги, бейджи
  similarity.py     локальный антиповтор
  transcribe.py     Whisper: голос, аудио, видео → текст
  youtube.py        настоящие видео для /hint
  net.py            запросы к Google только по IPv4
  keyboards.py      кнопки
  handlers/         start, admin, onboarding, skills, tasks, progress, submissions, fallback, errors
  llm/
    openrouter.py   единый клиент моделей: цепочки, повторы, лимиты, два провайдера
    models.py       состав ансамбля
    tree_pipeline.py · task_pipeline.py · eval_pipeline.py   дерево, задания и подсказка, оценка
tests/              258 тестов
```

### Кто что делает в ансамбле
Каждый шаг — цепочка моделей: первая рабочая отвечает, остальные запасные. В таблице ведущая модель.

| Шаг | Ведёт |
|---|---|
| Дерево: черновик, доработка | nemotron |
| Дерево: критика | gemma |
| Дерево: финальный судья | dots |
| Задание: предложение, `/hint` | nemotron |
| Задание: проверка новизны | gemma |
| Фото: анализ A | gemma |
| Фото: анализ B, «тогда vs сейчас» | dots (со зрением) |
| Скептик и оценка текста и голоса | nemotron |

Gemma везде идёт двумя копиями: сначала от Google (своя квота), потом от OpenRouter. У nemotron нет зрения, поэтому в шагах с картинками её нет.

### Данные (Firestore)
```
meta/owner                          кто владелец
users/{uid}                         разрешён ли, роль, имя
users/{uid}/skills/{skillId}        название, уровень, XP, серия, бейджи, ответы онбординга
  levels/{levelId}                  порядок, название, критерии, статус, сколько засчитано
  tasks/{taskId}                    описание, подсказка, тип пруфа, wildcard, закрыто ли
    attempts/{attemptId}            вердикт скептика, XP, пруф (тип, file_id, текст или расшифровка)
      media/proof                   байты пруфа (до 900 КБ, у документа лимит 1 МиБ)
```
Firebase Storage требует платного тарифа, поэтому пруфы лежат прямо в Firestore, плюс `file_id` Telegram как запасной указатель.

## 4. Как переживает бесплатные модели
- **Цепочки и повторы.** Каждой модели до 3 попыток с паузой 5 и 10 секунд. Сбоем считаются ошибка HTTP, пустой ответ, не-JSON и JSON не той формы.
- **Постоянные отказы** (HTTP 400, 401, 402, 403, 404: неверный ключ, кончились кредиты, модель недоступна) не повторяются — сразу следующая модель.
- **Лимит OpenRouter** (50 запросов в сутки на всё) определяется по заголовкам. Остальные его модели пропускаются, но Gemma от Google продолжает работать, поэтому бот не останавливается. Если не ответил никто, бот честно пишет про лимит.
- **Особенности Google:** запросы идут только по IPv4 (в некоторых сетях IPv6-маршрут до Google не работает), блок рассуждений `<thought>` вырезается перед разбором JSON.
- **Ничего не висит молча.** Любое исключение в обработчике превращается в ответ пользователю. Построение дерева идёт в фоне с защитой от дублей, генерации — с защитой от двойного нажатия.
- **FSM хранится в памяти**, после перезапуска состояние диалога пропадает; для пруфов это закрывает `/retry`.

## 5. Лимиты и скорость

| Что | Значение |
|---|---|
| OpenRouter, бесплатные модели | 20 запросов в минуту, 50 в сутки на все модели вместе |
| Gemma 4 на Google (бесплатный тариф) | 30 в минуту, 16 тыс. токенов в минуту, 14 400 в сутки на модель |
| Поиск YouTube | 100 поисков в сутки на проект, примерно 30–50 подсказок |
| Файл от пользователя | до 20 МБ |
| Архив пруфа в Firestore | до 900 КБ |
| Время на одной Google (замерено) | дерево уровней ~7 минут, задание ~50 с, оценка фото ~80 с |

Основное время уходит на «размышления» Gemma 31B. Её быстрая сестра gemma-4-26b-a4b (5–6 секунд на ответ) в боте пока не используется: качество не проверялось.

## 6. Безопасность
- Ключи и токены лежат в `.env` и ключе Firebase; оба файла в `.gitignore`. История git проверена на утечки перед каждой публикацией.
- Бот закрыт whitelist'ом; код активации сравнивается безопасно, а сообщение с ним удаляется из чата.
- Правила Firestore — deny-all: к базе имеет доступ только бот.
- Ключ YouTube ограничен одним API и передаётся в заголовке, а не в адресе, чтобы не попадать в логи.
- На бесплатных тарифах OpenRouter и Google запросы и фото могут использоваться провайдерами. Для личного бота это приемлемо, для публичного — нет.

## 7. Тесты
258 тестов, примерно столько же кода, сколько в самом боте, и все работают без сети и ключей:
- чистая логика (правила геймификации, антиповтор);
- слой данных на фейковом Firestore в памяти;
- клиент моделей на подменённых HTTP-ответах;
- пайплайны на заготовленных ответах моделей;
- сквозные тесты через настоящий диспетчер aiogram с фейковым Telegram: порядок роутеров, доступ, диалоги, кнопки.

Ключевая логика проверена мутациями: код намеренно ломается, и хотя бы один тест должен покраснеть.

## 8. Чего пока нет
- **Деплоя.** Бот отвечает, пока запущен процесс на компьютере; облако требует платёжного аккаунта.
- **Анализа видеоряда:** у видео оценивается только звук.
- **Ссылок на видео в самом сообщении задания:** они приходят только в `/hint`.
- **Эталонных решений** для задач с одним верным ответом (например, химия или математика) — отложено.
- **Сравнения «тогда vs сейчас» для старых работ:** у ранних попыток фото не архивировались, нужны две новые засчитанные фото-работы.
